# AGENTS.md — `hivemind-test-harness`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

The central integration test suite for the HiveMind network: topology,
stress, and cross-repo scenarios that span more than one repository. Part of
the [HiveMind](https://github.com/JarbasHiveMind) ecosystem — a protocol for
connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). The hub is
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core); the
in-process simulator (`TopologyBuilder`, `MasterNode`, `SatelliteNode`,
`RelayNode`, fixtures, assertions, preset scenarios) lives in
[hivescope](https://github.com/JarbasHiveMind/hivescope) and is a dependency
here, not reimplemented. Single-repo protocol tests belong in the owning
repo's `tests/e2e/` using hivescope directly; this repo is for scenarios that
need >1 relay hop, cross-language/embedded interop, real OVOS skill
execution, or sustained load.

## Layout / build / test

- Package module: `hivemind_test_harness/` (currently near-empty; the tests
  themselves are the deliverable). Tests live in `tests/`, plus one guard
  test in `test/` (`test/test_e2e_sharding.py`, asserts every
  `tests/test_e2e_*.py` module is covered by exactly one CI shard) — check
  both before adding a new test directory.
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[dev]" --prerelease=allow`
- Run the suite in the foreground:
  `pytest tests/ -v --timeout=60 -m "not slow"` (standard run, excludes
  stress/large-topology tests) or `pytest tests/ -v --timeout=120` to include
  them. `pytest test/` runs the sharding guard. Skill e2e
  (`tests/test_e2e_*.py`) needs a live OVOS install — the `ovos` extra.
  `tests/test_load_admission.py -m slow -s` starts a real Tornado listener
  (see below); `tests/test_js_e2e.py` needs Node.js.
- Most of the suite routes through hivescope's in-process loopback, which
  never loads a transport plugin — that is **routing conformance** (handshake
  sequencing, ACL decisions, message propagation across a topology), not
  transport/crypto coverage. `test_load_admission.py` is the exception: it
  boots the actual `HiveMindWebsocketProtocol` (fixture `tornado_hub`) because
  admission cost is paid on the listener's real IOLoop, which the loopback
  never exercises. Keep that distinction in mind when writing a new test —
  most scenarios want the loopback; only real concurrent-socket load needs
  the real listener.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is
  a bug to FIX at the source (usually in hivescope or one of the protocol
  repos), not to work around with a pin downgrade.

## Working agreement (org-wide law)

- **Git identity is always** `JarbasAi <jarbasai@mailfence.com>`. Never set a
  per-repo override.
- **Never push `dev` or `master`.** Work on a feature branch and open a
  **draft** PR into `dev`. A human merges. You do not merge your own PRs.
- **Never merge or modify `Release X → master` PRs.** They are the maintainer's
  stable-release mechanism, generated by automation.
- **One commit per PR** (squash before pushing). Conventional commits; `feat:`
  only for a user-visible new capability. `fix:`, `docs:`, `chore:`, `ci:`
  otherwise.
- **Disclose AI authorship.** Every PR/issue/comment an agent writes carries, at
  the top: `> 🤖 Auto-generated by <model> via Claude Code — NOT human-reviewed.
  Verify before acting.` PR bodies are plain human prose (3–6 short paragraphs),
  no tables or section-symbol spray.
- **Never edit someone else's** issue, PR description, or comment. Add a comment
  instead; on your own PRs, edit the body rather than piling on comments.
- Keep durable text (README, docs, PR bodies, comments) timeless and standalone:
  no dates, no "currently/now/new", no meta-commentary about the edit itself.
- No scratch files, committed virtualenvs, `__pycache__`, `.pyc`, `.egg-info`,
  or build artifacts in a PR. `git show --stat` shows only intended files.
- **Keeping this AGENTS.md current is a quality gate.** Any PR that changes this
  repo's conventions, build/test commands, dependencies, entry points, or
  observable behavior updates AGENTS.md in the same PR. A stale AGENTS.md is a
  review-blocking defect, the same tier as a failing test.

## Dependencies

- **Floor pins only** (`>=X.Y.Za1`), bumped when a feature or fix is actually
  needed — with a one-line comment saying why. This repo's `pyproject.toml`
  already does this rigorously (see the comments on `hivescope`,
  `hivemind-core`, `hivemind_bus_client`, and every `dev`-extra pin): each
  floor names the exact upstream fix or spec clause the corresponding test
  asserts outright. Follow that pattern for any new floor bump. No upper caps
  unless a specific released version is genuinely broken (say which and why).
- **No lockfiles, ever.** Target the latest alphas (`--prerelease=allow`,
  also set via `[tool.uv] prerelease = "allow"`).
- Everything in `pyproject.toml` (deps, metadata, version). Never install from
  git — depend on a published PyPI alpha. The README's `pip install
  hivescope @ git+...` line is stale against this rule; prefer the
  `pyproject.toml` floor pin instead.
- Apache-2.0. Do not add GPL/AGPL dependencies.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- **Routing conformance, not transport/crypto coverage.** Say so plainly when
  writing docs or a test module docstring: the in-process loopback (hivescope)
  never loads a transport plugin, so handshake framing, TLS, and wire-level
  crypto are covered by the protocol repos' own test suites, not here. Only
  `test_load_admission.py` runs against a real `HiveMindWebsocketProtocol`
  listener, and only for admission/load behavior, not crypto correctness.
- **`slow` marker discipline.** Anything that spins up a large topology or
  drives real sustained load is `@pytest.mark.slow` and stays out of the
  default CI run (`-m "not slow"`). `--strict-markers` is on: a new marker
  must be registered in `pyproject.toml`'s `markers` list or the run fails
  outright instead of silently no-opping.
- **The sharding guard is load-bearing.** `test/test_e2e_sharding.py` fails
  the build if a new `tests/test_e2e_*.py` module is added without also
  wiring it into a CI shard — do not silence or delete this test to make a
  new e2e module pass locally; wire the shard instead.
- **Load-test numbers are host-relative.** `test_load_admission.py` prints a
  latency distribution rather than asserting a threshold; absolute numbers
  are not portable across machines, and the reconnect-wave scenario reads
  slower than the first wave due to client-side `TIME_WAIT` pressure, not a
  listener regression. Do not turn these prints into hard thresholds without
  accounting for both effects.
- **hivemind-websocket-protocol is optional at import time.** The
  `tornado_hub` fixture skips (not fails) when it is missing, since it is
  only needed to run the real-listener load scenarios — do not make it a
  hard dependency of the base install.
